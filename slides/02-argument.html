Why Vibe Breaks in a Real Project

1

Context Dies with the Chat.

Put the context in the repo.

2

Intent Is Never Written Down.

Write a spec and a plan first.

3

Diffs Get Rubber-Stamped.

Keep each change small enough to review.

4

Everyone Prompts Differently.

Agree the rules once, or the codebase drifts.

“Structure scales, vibes don't.

Addy Osmani · The New Software Lifecycle, June 2026

20: 0:40 · 60: 1:00.

"These are the four ways vibe coding breaks once the work is in a real repo, not a one-off chat.
One: the context dies with the chat, so the next session starts from zero.
Two: the intent is never written down, so Done is whatever the model invents.
Three: nobody really reviews the diffs, so risky changes land on main.
Four: every person prompts their own way, so the codebase slowly falls apart."

"That is why I write the process into the repo. Context lives in files. Spec and plan before build. Small changes you can actually review. Shared rules, not a vibe you have to remember. Or, as Addy Osmani put it: Structure scales. Vibes don't."
