Each Station: One Tool, One Artifact, One Rule.

"Six stations. Ticket, context, spec and plan, build, review, hand-off. This is the software development lifecycle with an agent in it."

"The lifecycle before that was the same job. A ticket, then design, then build, then test, then ship. A person carried the context from step to step, and a person wrote the code."

"A person writing the code was the slow part. With AI, that part got fast. So the rest of the path has to adapt. The ticket has to be something an agent can start from. The context has to live in the repo, not in someone's head. The spec and the plan come before the code. You still read the diff, and a human still reviews andmerges."

"Each station has one tool, one artifact, and one rule. Let's look at the stations one by one."

Demo ticket · paste into Linear

DEMO-1 Ready

Training calendar shows the weather for today and tomorrow

Problem

Riders plan outdoor rides in the Training calendar, but they have to leave the app to check the weather.

Acceptance
  • Today and tomorrow show a weather chip in the day header: icon, high temperature, and rain % when it is over 30%.
  • The forecast uses the rider's location, not the default coordinates.
  • All other days look as they do today.
  • If the weather request fails, the calendar still loads, without the chip.
  • A test covers which days get a chip and the failure case. Copy in en and de.
Out of scope
  • No location override per day.
  • No bad-weather hints on sessions.
  • No change to the weather API or the mobile app.
Links
  • NPO-88 (Training page weather, full scope)
  • components/training/day-column.tsx, GET /api/weather
